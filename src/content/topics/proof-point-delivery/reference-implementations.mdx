<p class="sec-note">Globant built a custom middleware for a client's order management system (OMS). Like the Content Resolution API, it is custom code that other systems call in production: Magento Cloud calls it, and it runs on AWS, on one EC2 node behind a load balancer, with an RDS database. Its production metrics are the reference for running a custom layer of this kind.</p>

<div class="decide">
  <h4>What the reference shows, and what it does not</h4>
  <p>It shows a custom middleware in production with no timeouts, 2 server errors in 24 hours (0.003%), no failed status check, and recovery from a node failure in minutes. It runs on one fixed node, without autoscaling, and its daily peak uses under 13% of that node's estimated capacity.</p>
  <p>It does not show EG's volume. Its peak is about 6 requests a second, and the burst after a 1M send is estimated at 300 to 1,000. The resolver meets that through its design, not through the reference's sizing: every payload is cached in memory, nothing external is called on the request path, and instances are stateless, so they scale out (<a href="#performance">Performance at volume</a>).</p>
</div>
