title: Contentful never decides which variant is served
useCase: uc1
resolves: []
---

Who selects the variant is open (Q2). In option A, NBA reads a variant
index published out of Contentful and hands off the variant it picked. In
option B, NBA hands off the proof point, segment and tone, and the Content
Resolution API serves the one published variant written for them, or the
proof point's default copy.

*Why:* matches the stated pilot parameter, keeps personalisation
licensing off the critical path, makes the fetch deterministic and
cacheable. All three hold in both options.

*Consequence:* in option A the variant index feed is a first-class
deliverable, because NBA cannot choose between variants it has not been
told about — this is not in the brief's flow. In option B there is no
index, and the trace in EG's log system is the only record of which
variant each decision became.
