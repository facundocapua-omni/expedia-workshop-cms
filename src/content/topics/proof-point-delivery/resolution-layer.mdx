  <div data-origin="uc1:position:4" class="decide risk">
    <h4><span class="stamp">new</span>A thin resolution service sits between Contentful and the channels</h4>
    <p>Channels do not call the Contentful delivery API directly. A small stateless service — the <strong>Content Resolution API</strong> — parses the reference, serves an immutable published snapshot, applies and <em>reports</em> translation fallback, composes the message, and shapes the channel payload.</p>
    <p>This is the one net-new component in the design, and it needs saying plainly: the delivery API alone cannot satisfy three of the stated requirements. It serves only the latest published version, so "exactly the same content" breaks the moment an author republishes mid-campaign. Its locale fallback is silent, so a consumer cannot report on it. And it will not survive a burst of concurrent fetches after a newsletter send without a cache in front of it. If the guarantee is that every channel gets identical content, that guarantee has to be enforced in one place — otherwise the pilot proves consistency of input, not of output.</p>
  </div>

  <div data-origin="uc1:position:6" class="decide risk">
    <h4><span class="stamp">deferred</span>Grammatical agreement is out of POC scope, and has to be solved before production</h4>
    <p>For the POC, copy is plain text with named variables and a straight substitution at resolution time. Authors write one sentence per locale with no syntax beyond the variable itself. Number formatting follows the locale — thousands separators and decimal marks — but nothing in the sentence adapts to the value.</p>
    <p><strong>What this knowingly leaves broken.</strong> A value of 1 produces "seen 1 times". German and Thai degrade the same way. Arabic is worse: six plural categories, with the noun and any surrounding adjective changing alongside the number, so one sentence cannot be correct across the range. Ordinals and any gendered noun driven by the variable have the same problem.</p>
    <p><strong>Why it is acceptable here and nowhere else.</strong> The POC tests whether one authored source reaches every channel consistently, translated and versioned. Substitution proves that. But CMS-47 — composing the metric into a grammatically correct, locale-appropriate sentence — is one of the capabilities EG is evaluating, and the one they describe as a capability gain rather than an efficiency gain. Deferring it means that capability is <strong>demonstrated in principle, not proven</strong>, and the readout should say so rather than let it pass unremarked.</p>
    <p><strong>What full implementation needs.</strong> A plural-aware message format — ICU is the standard and every translation tool already parses it — with authoring that keeps the syntax away from the author: a plain source sentence expanded into plural categories by a generation step, approved once, and stored in the machine-readable form. Two things drive the cost: whether the real parameter types are counts only or also currency, dates and ordinals, and whether Arabic stays in the locale set. Four of the five pilot locales need at most two forms; Arabic alone accounts for most of the work.</p>
  </div>

  <h3>Option B in detail</h3>
  <Fragment set:html={optionB} />
  <ul class="tight">
    <li><strong>A reference wins.</strong> If the fetch carries <code>ref</code>, the resolver serves exactly that variant and version, as in option A. That is also how anyone replays what was sent.</li>
    <li><strong>Otherwise, the one variant written for the decision.</strong> The resolver looks up the published variant of the message for that segment and tone and serves its latest published version. Publishing a second variant for the same message, segment and tone is blocked at authoring, so the lookup never has to choose between two.</li>
    <li><strong>No such variant: the message's default copy.</strong> Reported as <code>selection: "default"</code>. No other variant is tried, so what goes out is either the copy written for this segment and tone or the approved generic copy, never a guess between them.</li>
    <li><strong>Missing translation: the variant in the source locale.</strong> Reported with <code>fallbackApplied</code>, as in option A. The partner gets the specific message in English rather than generic copy in their language.</li>
  </ul>
  <p>Nobody filters by channel before the fetch, so publishing also checks that every variant fits every channel profile, or carries an override for the one it does not fit.</p>
  <p>Every resolution writes one record to EG's log system: partner, channel, message, segment, tone, locale requested and served, the variant and version served or the default copy, and the <code>consistencyKey</code>. It is written off the request path. In this option the trace is the only answer to "what did this partner see, and where", because two surfaces can resolve the same decision to different versions. Channels still emit the served-variant event, and it becomes the only way NBA learns which variant its decision turned into.</p>
  <p>Option B is not the Contentful alternative in <a href="/sessions/nba-hand-off/#variant-metadata">Session 2's variant metadata</a>, where a personalisation product resolves segment and tone. Here NBA still decides what to say and in which tone. The resolver only finds the copy written for that decision, with a lookup that gives the same answer every time for the same published content.</p>

<h3>Alternatives considered</h3>

  <div data-origin="uc1:alternatives:1" class="decide risk">
    <h4>Channels calling the delivery API directly, no resolution layer</h4>
    <p>Fewest moving parts and closest to the source document's description. Not taken, for three reasons: the delivery API serves only the current published version, so version pinning is impossible and a mid-campaign republish silently changes what was sent; locale fallback is silent, so no consumer can report on it; and every channel would have to implement message composition independently, which reintroduces exactly the drift the pilot exists to eliminate.</p>
    <p>If EG wants the minimal version anyway, it is viable for the CRM and VMC payload comparison — but not for SFMC, and not for anything claiming immutability.</p>
  </div>
