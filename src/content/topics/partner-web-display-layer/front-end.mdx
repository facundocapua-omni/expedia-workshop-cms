<p class="sec-note">One party owns the front end end to end. The question is less who builds it than how the work splits once it is live.</p>

<div class="decide">
  <h4><span class="stamp">proposal</span>Globant builds and runs it, hosted by EG on AWS</h4>
  <p>Globant builds the partner web front end in Next.js and Tailwind and runs it in production, deployed with OpenNext to EG's own AWS account. The AWS account is EG's; Globant deploys to it and runs the front end there with delegated access.</p>
  <p>EG keeps the infrastructure, so a change of supplier is a handover of access rather than a hosting migration.</p>
</div>

<h3>Why Next.js on OpenNext</h3>
<ul class="tight">
  <li><strong>Backed beyond one vendor.</strong> OpenNext is open source and a member of the Next.js Ecosystem Working Group, the successor of the Deployment Adapters Working Group, together with Vercel's Next.js team, Netlify, Cloudflare, Google and AWS Amplify.</li>
  <li><strong>One reusable component library.</strong> React components that use EG's design system natively, so the library can serve more than partner web.</li>
  <li><strong>Ready for the roadmap.</strong> One framework for static pages now and for dynamic or authenticated surfaces later, in EG's own AWS account.</li>
  <li><strong>What EG and Globant take on.</strong> OpenNext is a community adapter: versions are pinned and upgrades planned, and the origin pattern behind Akamai is agreed with EG's Edge team.</li>
</ul>

<h3>The CDN in front of partner web</h3>
<p>EG has no CDN of its own today. Partner web is served through Adobe's, which comes with AEM and is decommissioned with it. The edge that routes between AEM and the new front end during the migration, and stays in front of the new front end after it, has to be in place first, and it has to be EG's.</p>

<div class="decide">
  <h4><span class="stamp">proposal</span>Akamai, in place before the first business case moves</h4>
  <p>EG puts Akamai in front of partner web. It goes live sending all traffic to AEM, so moving DNS to it changes nothing for visitors. From then on it routes each business case to AEM or to the front end on AWS and serves the redirects, and once AEM is gone the front end on AWS is its only origin.</p>
  <p>Globant recommends Akamai because it does at the edge what the migration needs: routing by path and by cohort between two origins, serving the redirects, and rolling back in minutes. It also belongs to neither origin, so it outlives AEM.</p>
</div>
