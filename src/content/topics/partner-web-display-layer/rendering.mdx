<p class="sec-note">Most of partner web is the same for every visitor and changes only when an author publishes. Pages are therefore built once and served from cache, and only what differs per visitor is rendered on each request.</p>

<div class="decide">
  <h4>ISR by default, SSR only where the page is private</h4>
  <p>Public pages use incremental static regeneration (ISR): they are rendered once, served from cache and regenerated when their content changes. Private sections, whose content depends on who is signed in, use server-side rendering (SSR) and are rendered for every request (D-36).</p>
</div>

<p>EG's CDN holds no pages on purpose. A page stored there would outlive the publish that replaced it, and every publish would then need a second purge, in a CDN the front end does not control. Private pages are never stored at levels 1 or 2, whoever asks for them.</p>

<h3>Performance</h3>
<p>Lighthouse runs during development and again in the deployment pipeline, against thresholds set to green scores. A deployment below them stops. It can still go out by an explicit bypass, and the regression is then logged as a bug (D-37).</p>
<p>Lighthouse measures in the lab, before release. The Core Web Vitals gate in the <a href="/sessions/aem-migration/#coexistence">migration ramp</a> measures real visitors after it. The first catches a regression before it ships; the second confirms the new front end is at least as fast as AEM on real traffic.</p>
